# v1.13 직접 조작 검증 · 2026-09-29

로컬 production build, `http://localhost:4174/?experience=relay`. 앱 내 브라우저의 실제 UI로 진행했다. 앱 상태/localStorage를 주입하거나 완료 상태를 강제로 변경하지 않았다. 기존 테스트 기록에서 시작하여 식사부터 완주까지 진행했다.

## 확인한 행동

1. 시장→식당 진입, 식탁 안내, 찜닭 주문. 새 목적지 방향 표시와 바닥 표식 확인.
2. 음식 조각을 바깥에 놓으면 0/3 유지·접시 복원. 입 안내에 직접 놓으면 1/3. 취소 후 다시 열면 0/3과 음식 복원. PC에서 직접 세 입 완료.
3. 390×844 화면에서 다시 직접 세 입 완료. 식사 확인 후 영수증 안내와 계산대 목적지 표시. `meal-one-bite.png`, `mobile-direct-meal.png`.
4. 계산/영수증 수령. QR은 기존 정렬 도움 기능을 사용하고 정렬 유지 후 확인했다. 이번 차수에서 QR 드래그를 새로 검증했다는 의미는 아니다. 직접 QR 드래그 증거는 v3 기록에 있다.
5. 식당 밖 골목→공방 두 연결 구간 진행. 쿠폰 보유 상태가 연결 화면과 새로고침 후 유지된다.
6. 전통주 선택, 20,000원 예시에서 10%/2,000원 할인 접수. 누룩 먼저 드래그 시 쌀부터 안내. 쌀·누룩·물을 각각 발효 항아리로 드래그해 3/3. 실제 도구를 눌러 발효→소주고리→수집 진행. 술병 선택 후 표찰을 술병에 직접 드래그하고 포장 선택. `soju-material-drag.png`, `soju-label-package.png`.
7. 국화차로 바꾼 뒤 꽃 세 송이를 직접 다관에 드래그. 10% 물에서 양 확인 시 부족 안내, 60%에서 성공. 물 붓기/찻잔 따르기는 10%씩 붓기 버튼으로 확인. 마우스를 오래 누른 실제 물줄기 영상은 촬영하지 않았으며, 주둥이→용기 좌표/65% 유지와 취소 복원을 단위 검사로 검증했다. `tea-poured.png`.
8. 탈 바탕색/표정은 표면을 직접 드래그. 볼 색은 키보드 구역별 색칠 버튼 이용: 첫 입력 4/14, 네 번 입력 후 완료. 실제 텍스처에 색이 추가되고 한 번의 도움 클릭으로 완료되지 않는다. `mask-painted.png`.
9. 공방→승차장→차량 문, 연결차량 이동, 하차→강변→월영교, 월영정 산책, 강변→팝업 연결을 모두 진행했다. 체험을 바꿔도 원래 전통주에 쓴 2,000원 혜택이 유지된다. `bridge-with-relay-benefit.png`.
10. 투호 작업을 취소하면 0/0 유지. 항아리 바깥을 직접 조준해 0성공/1회, 입구를 직접 조준해 1성공/2회. 새로고침 후 동일 기록 복원. 성공 화살은 항아리에, 실패 화살은 주변 바닥에 표시된다. `tuho-result-persisted.png`.
11. 모바일390×844에서 세 번째 화살을 입구에 직접 조준해 2성공/3회. 네 번째 시도 버튼 비활성. `mobile-tuho-completed.png`.
12. 완주 확인: 식사·혜택·체험·이동·월영교/팝업 다섯 연결 완료, 세 전통 체험, 할인 예시2,000원. `mobile-relay-completed.png`.

## 자동 검사와 한계

- `tests.txt`: 133 통과, 0 실패. 식품 잡기/놓기·취소/카메라 복원·중복 방지·키보드 세 입, 혜택 적용 프로그램 고정, 투호 두 축 오차, 물줄기/용기 위치와 취소 복원 포함.

- 모바일은390×844 브라우저 viewport 검사이며 실제 휴대전화/GPU 성능 측정은 아니다.
- 실측/실사 공간, 연속된 실제 도시, 교통 AI, 강체·액체 물리 엔진, 실제 QR·가맹점·결제 연동은 구현 범위 밖이다. 짧게 연결한 3D 거점과 직접 조작하는 시연이다.
- 새 사진 다운로드는 하지 않았다. 기존 사진 대조 구조/PBR 재질을 재사용했다.
